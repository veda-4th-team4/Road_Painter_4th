# cctv_app

Hanwha OpenSDK 5.00 카메라에서 ArUco 마커를 검출하고, 카메라 내부 보정과
픽셀→월드 호모그래피를 시험·검증하는 **관리자·시운전용 앱**이다. 이 디렉터리는
카메라에서 도는 `.cap` 앱만 담는다. 명령 전송·상태 표시·스냅샷 저장을 담당하는
관리자 대시보드는 이 저장소의 `Server/admin_console/`에 있다.

> 문서 대조일: 2026-07-30  
> 기능 플래그·기본 보정값의 최종 기준: `inc/app_config.h`  
> 배포별 네트워크 값: Git에서 제외된 `inc/app_config_local.h`, `config.sh`

## 시스템 구성

```text
PNO-A9081RG / cctv_app.cap
  ├─ raw NV12 1920×1080 프레임에서 ArUco 검출
  ├─ TCP pose/명령 ──────────────> 관리자 대시보드 :7000
  ├─ TCP 스냅샷 ─────────────────> 관리자 대시보드 :7001
  └─ TLS HELLO/POS ──────────────> 중앙 서버 :9000

브라우저 <─────────────────────── 관리자 대시보드 :8083
```

관리자 대시보드는 `Server/admin_console/`의 `web_gui.py`이며 카메라 관련 화면은
`cctv.py`가 담당한다. 포트는 기본값이고 실행 인자 또는 `config.sh`로 바꿀 수 있다.
실제 IP, 계정, 인증서는 문서에 기록하지 않는다.

카메라는 컴파일 시점에 정해진 한 포트로만 접속하므로(`POSE_SERVER_PORT`), 대시보드
인스턴스가 여러 개일 때 카메라를 받는 쪽은 항상 하나다.

## 현재 구현

- `DICT_4X4_50` ArUco 검출, 코너·중심·처리시간을 `CAM_POSE`로 전송
- ChArUco 기반 K/dist 캘리브레이션과 캡처 품질 게이트
- 계산 앵커를 이용한 온카메라 H 계산 및 독립 검증 마커 오차 표시
- `HG_SET`, `HG_SAVE`, `HG_QUERY`를 통한 외부 H 적용·저장·조회
- `raw`와 `undistort` H 좌표 모드 지원 및 모드 메타데이터 저장
- 로봇 마커 높이와 카메라 실측 높이를 이용한 마커 평면 시차 보정
- 12점 후보 수집, CSV/JSON 내보내기, PC의 12C8 조합 분석
- ROI·탐색 패스·동적 ROI를 이용한 검출 성능 조정 및 명시적 저장
- 관리자 대시보드의 캘리브레이션, 호모그래피, 마커 검출, 서버 송신, Shell 탭
- 중앙 서버 legacy TLS 클라이언트: 서버 인증, 비차단 재연결, `HELLO`/raw `POS`,
  `H_MATRIX` 전달, 제한된 `CALIB_START` 수신

중앙 TLS 프로토콜 전체 v2는 아직 구현 완료 규격이 아니라 설계 초안이다. 현재 코드와
목표 규격을 혼동하지 않는다.

## 호모그래피 기준

현재 `cctv_app`의 컴파일 기본값은 다음과 같다.

| 구분 | 기본 ID | 역할 |
|---|---|---|
| 계산 앵커 | `0..7` | 8개가 모두 보이는 유효 프레임 30장을 모아 H 계산 |
| 검증 마커 | `9..17` | H 피팅에서 제외하고 독립 오차만 계산 |

앵커·검증 목록과 월드 좌표는 대시보드에서 런타임 변경할 수 있다. 기본 좌표는 예시이므로
현장 설치 전 마커 **중심**의 실측 mm 좌표로 교체해야 한다. 별도 `cctv_runtime`
설계 초안의 `10..17`/`20..23` ID는 이 앱의 현재 기본값이 아니다.

H를 만들고 적용할 때 픽셀 좌표 모드는 반드시 같아야 한다.

- `raw`: 검출된 원본 픽셀 코너를 그대로 사용한다.
- `undistort`: K/dist로 보정한 픽셀 좌표를 사용한다.
- 마커 높이 평면용 `H_marker` 유도는 핀홀 모델이 필요하므로 `undistort` 모드에서만
  허용된다.
- 검증 마커는 어떤 모드에서도 H 피팅에 포함하지 않는다.

## 빠른 시작

배포 설정 템플릿을 복사해 실제 값을 로컬 파일에 입력한다.

```bash
cp inc/app_config_local.h.example inc/app_config_local.h
cp config.sh.example config.sh
```

`POSE_SERVER_IP`와 `POSE_SERVER_PORT`는 대시보드를 띄운 호스트와 포트를 가리켜야
한다. 이 값은 컴파일 시점에 박히므로 바꾸면 `.cap`을 다시 빌드해야 한다.

관리자 대시보드는 별도 컴포넌트이므로 `Server/admin_console/`에서 띄운다.

```bash
cd ../Server/admin_console && python3 -u web_gui.py 7000 8083 7001
```

인자는 순서대로 pose·명령 포트, HTTP 포트, 스냅샷 포트다. `start.sh`를 쓰면
`config.sh`의 값으로 백그라운드 실행된다.

## 빌드와 배포

카메라 앱은 OpenSDK 크로스 빌드 환경에서만 빌드한다.

```bash
make
opensdk_packager
```

`opensdk_packager`는 `IPCameraManifest.xml`과 서명 번들을 필요로 한다. 둘 다 SDK가
제공하는 산출물이라 이 저장소에서는 제외했으므로, 빌드 전에 OpenSDK 샘플에서 가져와
작업 사본에 둔다.

생성된 `cctv_app.cap`을 카메라 웹 UI의 Open Platform 화면에서 설치하고 앱을
재시작한다. 대시보드 호스트에서 `.cap`을 빌드하지 않는다.

카메라 앱의 온카메라 웹페이지는 SDK 샘플 템플릿에서 손대지 않았고 실제 기능이 없어
저장소에 포함하지 않았다. 관리자 UI는 `Server/admin_console/`의 대시보드다.

## 문서

설치 후 캘리브레이션·검증 순서, 좌표계와 `H_floor`/`H_marker` 정의, CCTV·서버·QT
메시지 규격은 별도 문서로 관리하며 이 저장소에는 포함하지 않았다. 필요하면 CCTV
담당자에게 요청한다.

날짜별 실험 결과와 과거 작업 기록, 팀 회신 원문도 저장소 외부에 보관한다.

## 안전과 기준 파일

- `ENABLE_SHELL_CMD=1`은 인증 없는 실험실 진단 기능이다. 외부망이나 운용 앱에
  포함하지 않는다.
- 실제 주소·계정·인증서·키는 Git과 문서에 넣지 않는다.
- H 적용과 저장은 분리돼 있다. RAM 적용 후 재부팅 보존이 필요할 때만 `HG_SAVE`한다.
- `PERSIST_TO_MNT`와 저장 경로의 실제 동작 여부는 카메라에서 확인한다.
- 코드와 문서가 다르면 `inc/app_config.h`와 명령 디스패처 구현을 우선한다.
