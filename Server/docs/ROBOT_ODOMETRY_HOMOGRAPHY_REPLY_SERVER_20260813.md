## 1. 🔴 §5-2 — 전제가 8/13부터 깨졌습니다. 재시도 전에 필요합니다

회신 §5-2에 이렇게 쓰셨습니다:

> 서버 세션은 `CALIB_DONE` 시점에 이미 닫혀 있어 대기가 걸리지는 않지만

**8/12까지는 맞았고, 지금은 ADMIN 개시일 때만 맞습니다.**

8/13에 Qt 개시를 열면서 세션 수명을 개시자별로 갈랐습니다. Qt는 종결 응답
하나(`H_MATRIX` | `CALIB_FAIL` | `CALIB_CANCELLED`)로만 대기 화면을 풀기
때문에, `CALIB_DONE`에서 세션을 닫아버리면 Qt를 닫아줄 주체가 사라집니다.

| 개시자 | `CALIB_DONE` 이후 |
|---|---|
| ADMIN | 세션 종료 (예전 그대로) |
| **QT** | **`calib_odo_result_wait_ms`(60초) 동안 `H_MATRIX`/`CALIB_FAIL` 대기** |

그래서 지금 상태로 **Qt가 개시한 세션에서 피팅이 실패하면** 이렇게 됩니다:

```
카메라: 피팅 실패 -> ODOM_DONE 으로 대시보드에만 통지, central 링크는 침묵
서버  : 60초 대기 -> CALIB_FAIL{timeout} 으로 세션 종료
Qt    : "카메라 응답이 없어 중단했습니다"   ← 실제 원인은 유효점 부족
```

원인이 조작자에게 **틀리게** 전달됩니다. `too_few_points`/`fit_failed`는
Qt가 이미 전용 문구를 갖고 있어서(각각 "조명과 사각형 크기를 확인하세요",
"다시 시도하세요"), 그쪽이 한 줄 보내주시면 그대로 뜹니다.

서버는 받을 준비가 돼 있습니다 — 결과 대기 구간의 `CALIB_FAIL`을 종결
응답으로 처리하는 경로가 이미 있고 회귀 테스트도 있습니다
(`router_odocalib.cpp`, `tools/odo_session_test.cpp` T4b).

> **판단**: 관리자창으로만 재시도할 거면 지금도 무해합니다. Qt 개시를 켜는
> 시점부터는 필요합니다. 저희는 첫 재시도를 관리자창으로 할 예정이라
> **재시도를 막지는 않습니다** — 다만 Qt 통합 시험 전에는 들어와야 합니다.

## 2. §5-1 — Qt는 `marker_height`를 읽지 않습니다

`_mm`도 `_m`도 아닙니다. **읽는 코드 자체가 없습니다.**

Qt 최신 브랜치(`ch4_qt_client_only`, 8/13) `Client/` 전체에서 `marker_height`
검색 결과 **0건**입니다. 리포 전체로 넓혀도 소비자가 없습니다:

| 주체 | 이 필드를 |
|---|---|
| 서버 | 파싱하지 않고 raw 보존·중계만 (`Calib::raw`) — 정확히 보신 대로입니다 |
| Qt | 읽지 않음 (검색 0건) |
| 카메라 | 자기가 만들어 싣는 값 |
| 문서 | `_mm`(wire·정본·EXEC_PLAN) vs `_m`(TESTING 픽스처·server_PROTOCOL) 혼재 |

즉 지금은 **기록용 필드**입니다. 시차 보정은 그쪽이 `H_marker`를 직접 분해해
`H_floor`를 역산하는 것으로 끝나고 있어서, 이 값이 0이어도 좌표가 틀어지지
않습니다.

`marker_height_mm`(mm)으로 통일하신 방향이 맞습니다 — 현행 문서 다수와 wire
확정본이 그쪽입니다. 저희도 `TESTING.md` 픽스처와 `router.cpp` 주석의 `_m`
표기를 같이 정리하겠습니다. **다만 소비자가 없으므로 재시도를 막는 항목이
아닙니다.**

## 3. §4 — (a) 세분화 부탁드립니다

서버 동작은 (a)/(b)가 동일합니다. 실제로 서버는 5종을 **이미 전부** 세션
수준으로 처리하고 있어서, (b)를 택해도 서버 코드는 손댈 게 없습니다
(`router_odocalib.cpp`의 세션 수준 사유 목록에 `no_intrinsics`,
`session_conflict`, `detect_off`, `session_refused`, `store_failed` 전부 포함).

**그래도 (a)를 부탁드리는 이유는 Qt 문구입니다.** Qt의 실패 사유 표에:

| reason | Qt 조작자 문구 |
|---|---|
| `no_intrinsics` | "카메라 내부 보정(체커보드)을 먼저 완료하세요." |
| `session_refused` | (표에 없음 → 서버 `msg` fallback) |

`no_intrinsics`로 오면 조작자가 **다음에 뭘 해야 하는지** 바로 압니다.
`session_refused`로 뭉뚱그리면 "세션이 거부됐다"까지만 전달되고, 정작
해결책인 "체커보드부터"가 사라집니다.

작업량이 작다고 하셨으니 (a)로 부탁드립니다. `session_refused`는 나머지
2종(정적 앵커 수집 중 / raw 좌표 모드)의 사유로 그대로 두시면 됩니다.

**§4 말미의 동작 차이(`store_failed`/`detect_off`를 지점 수준으로 보고)는
그대로 두셔도 됩니다.** 서버가 받는 즉시 중단시키고 `CALIB_CANCEL`로 정리를
요청하므로 결과가 같다는 판단에 동의합니다.

## 4. §6 — `cmp_scale` 받고 싶습니다

폐합오차가 균일 스케일 오차를 원리적으로 못 잡는다는 지적이 정확합니다.
네 변이 같은 비율로 짧으면 궤적이 실제로 닫힌다는 것, 그리고 바퀴 지름
오차가 정확히 그 형태라는 것 — 저희가 "진단 전용"으로 둔 이유보다 더
정확한 설명입니다. wire §5-1에 이 한계를 명시해 두겠습니다.

**새 메시지는 만들지 말아주세요.** 서버가 `H_MATRIX` 번들을 값 변경 없이
raw 보존하므로, 번들에 필드로 얹어주시면 그대로 저장되고 저희가 로그 한 줄
추가하면 끝납니다:

```json
{ "...": "...", "cmp_scale": 0.9987, "closure_mm": 12.4 }
```

`cmp_scale`이 1.000에서 유의하게 벗어나면 로봇팀에 바퀴 지름 실측을 요청할
근거가 됩니다. 지금은 그 신호가 대시보드에만 있어서 서버 로그·Qt 어디에도
남지 않습니다.

## 5. §2 — `image_size` 폴백은 거부로 바꾸는 걸 권합니다

§2 표에 *"미수신 시 `[2592,1520]`"* 로 적으셨는데, 이건 **틀린 값을 자신
있게 실어 보내는 경로**입니다.

실제 프레임이 다른데 보고가 안 된 상황이면 번들이 거짓말을 하고, 받는 쪽은
검증할 방법이 없습니다. `image_size`가 틀리면 Qt가 디코딩하는 해상도와의
비율만큼 좌표가 통째로 어긋나는데, 값이 그럴듯해서 아무도 눈치채지
못합니다 — `K`/`D` 누락이 90건 쌓이는 동안 아무도 몰랐던 것과 같은
실패 양상입니다.

`K`/`D`처럼 **없으면 전송 거부**가 일관됩니다. 세션이 실패하는 편이
조용히 틀린 좌표로 운용되는 것보다 낫습니다.

## 6. §3 — K/D 캐시 수정, 확인했습니다

`CALIB_K_QUERY` 응답에서도 캐시를 채우도록 한 수정이 **이미 저희 리포
작업트리에 들어와 있습니다**(`Server/admin_console/cctv.py`, 8/13 주석 포함).
"배포 대기"라 하셨는데, 코드는 여기 있고 **커밋과 관리자창 재시작만** 남았습니다.
저희가 같이 처리하겠습니다.

§3-1의 진단(이 경로가 카메라를 통과하지 않는다)도 코드로 확인했습니다.
저희가 "카메라 게이트가 안 걸린 것 같다"고 쓴 건 절반만 맞았고, 정확히는
**게이트가 있는 경로를 아예 안 지나간다**는 그쪽 설명이 맞습니다.

§3-3 조립기 이관은 **첫 통합주행 성공 이후**에 하시는 데 동의합니다.
지금 급한 건 `K`/`D`뿐이고 그건 §3-2로 메워집니다.

## 7. 재시도 준비 — 늦는 쪽은 저희입니다

카메라 쪽 체크리스트 4건(앱 Start / 검출 ON / K·dist / undistort 모드)은
재시도 직전에 맞춰주시면 됩니다.

**저희 쪽에 먼저 처리할 것이 남아 있습니다:**

| 항목 | 상태 |
|---|---|
| 서버 재시작 | ⚠️ 운영 :9000이 아직 8/12 22:28 바이너리 — Qt 개시·소유권·폐합오차 로그 전부 미적용 |
| 관리자창 커밋·재시작 | ⚠️ 주행 캘리 UI와 §3-2 K/D 수정이 커밋 대기 |
| CH2 전역 캘리 슬롯 | ⚠️ 8/13 15:14 저희 회귀 테스트가 운영 서버에 잘못 붙어 테스트 번들(`calib_id:"odom-test"`)로 덮었습니다. 원본은 계정 저장본에 남아 있고 복원 예정입니다 — 그 사이 저장된 CH2 번들을 보시면 무시해주세요 |

**재시도 일정은 위 3건을 처리한 뒤 저희가 먼저 제안드리겠습니다.**
200×200mm로 첫 지점 ack만 확인하는 것부터 시작하는 데 동의합니다.
