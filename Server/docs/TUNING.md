# 튜닝 파라미터

> **이 값 어디서 바꾸지?** 에 답하는 문서.
> 관련: [ARCHITECTURE](ARCHITECTURE.md) · [PATH_GEOMETRY](PATH_GEOMETRY.md) · [PROTOCOL](PROTOCOL.md)

튜닝 상수는 **코드에 없다.** 전부 [`config/params.json`](../config/params.json)에 있고,
서버가 시작할 때 읽어 **적용된 값을 전부 로그로 남긴다.**

```
값을 고친다 → 서버만 재시작한다 → 끝. 재컴파일 불필요.
```

- 항목 정의(타입·기본값·설명)는 [`src/params.hpp`](../src/params.hpp)의 `RP_PARAM_LIST` 한 곳에 있다.
  매크로 한 줄을 추가하면 구조체 필드·JSON 로딩·검증·로그가 전부 자동 생성된다.
- `_` 로 시작하는 키는 주석 취급하고 무시한다.
- 항목을 지우거나 빼도 된다 — 빠진 항목은 코드의 기본값을 쓴다.
- 오타로 모르는 키를 넣으면 `[WARN] params '...' - 모르는 항목 (오타?) 무시` 가 뜬다.

기동 로그에서 실제 적용값을 확인할 수 있다.

```
[INFO] 파라미터 파일 적용: config/params.json
[INFO] ----- 적용된 파라미터 -----
[INFO]   pen_offset_m           = 0.172    펜(노즐)이 마커 중심 뒤로 떨어진 거리 a
...
```

## 1. 기하 — 로봇 하드웨어 실측값

| 키 | 기본값 | 현재 설정 | 의미 |
|---|---|---|---|
| `pen_offset_m` | `0.150` | `0.172` | 펜이 마커 중심 **뒤로** 떨어진 거리 `a` |
| `pen_width_m` | `0.05` | `0.06` | 펜이 실제로 칠하는 폭 `w`. `0`이면 두께 보정이 통째로 꺼진다 |
| `wheel_base_m` | `0.166` | `0.166` | 좌우 바퀴 축간거리 `W`. 호에서 안쪽 바퀴 역회전 경고 판정에만 쓴다 |
| `min_paint_radius_m` | `0.200` | `0.200` | 도색 가능한 최소 펜 반지름. 미만이면 도면을 거부한다(`arc_too_tight`) |

🔴 **`pen_offset_m` 과 `pen_width_m` 은 자로 잰 값을 넣어야 한다.**
마커 사양(5cm)이 아니라 실제로 직선 한 줄 긋고 재야 한다 — 압력·속도·노면에 따라 달라진다.
`pen_offset_m` 은 로봇 쪽 값과 **자동으로 동기화되지 않는다.** 한쪽만 고치면 조용히 어긋난다.

⚠️ `min_paint_radius_m = 0.200` 은 기하가 아니라 **모터 한계**다.
호에서 바깥 바퀴 속도가 `1/R_robot` 로 발산해서, `0.200` → 약 1278 SPS(권장),
`0.180` → 약 1450 SPS(마진 하한). NEMA 17 은 2000 SPS 를 넘으면 탈조 위험이 있다.
로봇의 호 주행 속도가 바뀌면 이 값도 다시 계산해야 한다.
자세한 유도는 [PATH_GEOMETRY](PATH_GEOMETRY.md)에 있다.

## 2. ALIGN — 회전 직후 각도 정렬

| 키 | 기본값 | 현재 설정 | 의미 |
|---|---|---|---|
| `align_threshold_deg` | `2.0` | `1.0` | 이 각도 이내면 정렬 완료로 보고 `GO` |
| `align_max_tries` | `6` | `6` | 한 지점에서 최대 반복 횟수. 다 쓰면 포기하고 `GO` |

로봇이 감속 접근으로 오버슛을 줄이면 임계값을 더 내릴 수 있다.

## 3. MORE — 이동·호 직후 거리 보정

| 키 | 기본값 | 현재 설정 | 의미 |
|---|---|---|---|
| `more_deadband_m` | `0.005` | `0.005` | 이 거리 이내면 보정하지 않고 `GO` |
| `more_max_m` | `0.5` | `0.5` | 이보다 큰 보정량은 pose 가 틀렸다고 보고 **판정 폐기** + `GO` |
| `more_max_tries` | `4` | `4` | 한 지점에서 최대 반복 횟수 |
| `paint_undershoot_m` | `0.02` | `0.02` | 도색 직선을 **일부러 이만큼 덜** 명령하고 남은 만큼을 `MORE` 가 채운다 |

### `paint_undershoot_m` 을 건드릴 때 주의할 것

개루프로 한 방에 가면 지나치기 쉬우므로, 일부러 덜 명령하고 **CCTV 실측 기준으로 메우는** 방식이다.

```
도색 move 명령값 = max(min_move_m, (L + w) - paint_undershoot_m)
MORE 목표        = 그대로 (줄이지 않는다)
```

- 🔴 **목표 좌표는 줄이지 않는다.** 명령만 줄여야 그 차이가 다음 지점에서 오차로 잡히고 `MORE` 가 메운다.
  목표까지 같이 줄이면 메울 오차가 사라져 그냥 짧게 그은 선이 된다.
- 보정 시점에는 노즐이 아직 내려가 있어서 남은 구간도 이어서 칠해진다.
- 호(`arc`)와 비도색 이동에는 적용되지 않는다. `0` 이면 종전 동작 그대로다.
- ⚠️ **`more_deadband_m` 보다 커야 의미가 있다.** 이하로 두면 `MORE` 가 "보정 불필요"로
  판정해 **덜 그은 채로 끝난다.** 서버가 기동할 때 `WARN` 을 남긴다.
- `more_max_m` 을 넘겨도 판정이 폐기되므로, 서버가 자동으로 `more_max_m` 까지 내린다.

## 4. 판정 대기 창

| 키 | 기본값 | 현재 설정 | 의미 |
|---|---|---|---|
| `feedback_wait_ms` | `1000` | `1000` | `READY` 수신 후 판정까지 **고정 대기**. 이 동안 `POS` 를 모아 평균낸다 |

로봇의 미세 회전(0.1~0.3초)이 CCTV → pose 반영보다 빨라서 필요하다.
줄이면 회전 전 각도로 판정해 같은 `ALIGN` 이 반복된다.
대기 동안 모인 `POS` 는 버리지 않고 theta 평균(sin/cos 누적)에 써서 노이즈를 `1/√N` 로 줄인다 — 추가 지연은 없다.

🔴 로봇 입장에서는 응답이 최악 `feedback_wait_ms + α` 만큼 늦어질 뿐이므로,
**`READY` 에 자체 타임아웃을 걸어 임의로 출발하면 안 된다.**

| 키 | 기본값 | 현재 설정 | 의미 |
|---|---|---|---|
| `drift_period_ms` | `400` | `400` | 최소 전송 간격 |

| 키 | 기본값 | 현재 설정 | 의미 |
|---|---|---|---|
| `pos_lost_ms` | `2000` | `2000` | 마지막 채택 `POS` 로부터 이만큼 지나면 `HOLD` |
| `pos_recover_frames` | `2` | `2` | `HOLD` 해제에 필요한 연속 채택 장수 |
| `pose_gate_base_deg` | `3.0` | `3.0` | 이상치 게이트 상수항 (측정 노이즈 몫) |

🔴 **상한을 두지 말 것** — `POS` 가 느린 현장에서 정상 회전을 잘라낸다.

## 8. 캘리브레이션 세션 (정적 앵커)

| 키 | 기본값 | 현재 설정 | 의미 |
|---|---|---|---|
| `calib_timeout_ms` | `180000` | `180000` | `CALIB_START` 후 종결 응답이 없으면 `CALIB_FAIL{timeout}` |
| `calib_cancel_ack_ms` | `5000` | `5000` | `CALIB_CANCEL` 후 `CALIB_STOPPED` 를 기다리는 한도 |

🔴 `calib_timeout_ms` 는 **Qt 자체 타임아웃(5분)보다 반드시 짧아야 한다.**
서버가 먼저 접어야 Qt 가 이유를 모른 채 5분을 기다리지 않는다.

## 9. 캘리브레이션 세션 (오도메트리 주행)

| 키 | 기본값 | 현재 설정 | 의미 |
|---|---|---|---|
| `calib_odo_timeout_ms` | `300000` | `300000` | 주행 데드라인 (`CALIB_START` → `CALIB_DONE`) |
| `calib_odo_result_wait_ms` | `60000` | `60000` | `CALIB_DONE` 후 카메라의 계산 결과를 기다리는 한도 |
| `calib_capture_timeout_ms` | `15000` | `15000` | `CALIB_CAPTURE` 후 카메라 ack 한도 |
| `calib_odo_max_side_m` | `10.0` | `10.0` | 사각형 한 변의 **상한** |
| `marker_offset_m` | `0.0` | `0.0` | 마커 중심이 회전 중심에서 진행방향으로 떨어진 거리 |

⚠️ `calib_odo_timeout_ms` 는 **ADMIN 개시 세션에만** 그대로 적용된다.
QT 개시 세션은 Qt 대기 한도(10분)에 맞춰 서버가 알아서 깎는다(`Router::odoDriveBudgetMs`).
정적 앵커 방식(5분)과 대기 한도가 다르다.

🔴 `calib_odo_max_side_m` 은 **안전 장치**다. 이 값이 그대로 로봇의 실제 주행 거리가 된다 —
`90` 을 `900` 으로 잘못 치면 로봇이 9 m 사각형을 그린다.
Qt 는 하한만 검증하고 상한이 없으며 관리자 창의 브라우저 검증은 개발자도구로 우회되므로,
**서버의 이 값이 두 개시 경로 공통의 유일한 방어선이다.**

## 서버가 기동할 때 잡아주는 것

`sanitize()` 가 다음을 검사해서 로그로 알린다. 값을 고쳤으면 기동 로그를 한 번 보는 게 좋다.

| 검사 | 동작 |
|---|---|
| 음수·0 이하 값 | 하한으로 올리고 `WARN` |
| `pen_width_m / 2 > pen_offset_m` | `WARN` (펜이 마커보다 앞에 있는 꼴) |
| `paint_undershoot_m <= more_deadband_m` | `WARN` (덜 그은 채로 끝난다) |
| `paint_undershoot_m > more_max_m` | `more_max_m` 로 내리고 `WARN` |
| `min_paint_radius_m < pen_offset_m` | `WARN` (기하 하한 미만) |
| `calib_timeout_ms` > Qt 대기 한도 | `WARN` |
| 모르는 키 | 무시하고 `WARN` (오타 탐지) |
