## 1. 오도메트리 캘리 Qt 개시 지원

기존에는 관리자 창 전용이었고 Qt 요청은 명시적으로 거절했습니다. 그 근거는
"세션이 `CALIB_DONE`에서 끝나는데 `H_MATRIX`는 그 뒤에 오므로 Qt 대기 화면을
여닫는 짝이 성립하지 않는다"였습니다. **그 짝을 성립시켰습니다.**

### 핵심: 세션 수명이 개시자에 따라 갈립니다

```
... 주행 완료 → Server → CCTV: CALIB_DONE → [카메라가 H 계산] → H_MATRIX
                              ↑
                       여기서 세션을 닫는가?
```

| | ADMIN 개시 | QT 개시 |
|---|---|---|
| `CALIB_DONE`에서 | `clearCalib()` — 종료 (**기존 동작 그대로**) | `odoAwaitingResult_` — **세션 유지** |
| 뒤늦은 `H_MATRIX` | `request_id` 없이 중계 | 종결 응답으로 처리 |
| 뒤늦은 `CALIB_FAIL` | 버려짐 | Qt에 전달 |

QT 세션을 `CALIB_DONE`에서 닫으면 두 가지가 동시에 깨집니다 — `H_MATRIX`가
종결로 안 잡혀 `request_id`가 안 실리고, 카메라의 `CALIB_FAIL{too_few_points}`이
"진행 중인 세션 없음"으로 버려집니다. **둘 다 조작자를 대기 화면에 가둡니다.**

### 타임아웃 예산

`calib_odo_timeout_ms`(300초)에는 상한 클램프가 **일부러 빠져** 있었습니다 —
근거가 "Qt가 트리거하지 않으므로 5분 제약이 없다"였는데, 그 전제가 깨졌습니다.

값 자체를 깎으면 ADMIN 세션까지 짧아지므로, 클램프를 **세션 단위**로 옮겼습니다:

| 개시자 | 주행 데드라인 |
|---|---|
| ADMIN | `calib_odo_timeout_ms` 그대로 (300초) |
| QT | `min(300초, 290초 − calib_odo_result_wait_ms)` = **230초** |

신규 파라미터 `calib_odo_result_wait_ms`(기본 60초)는 `CALIB_DONE` 이후 카메라의
H 계산을 기다리는 구간입니다. 이 구간에서는 정지 핸드셰이크를 건너뜁니다 —
로봇은 이미 서 있어서 **세울 대상이 없기 때문**입니다.

### Qt에 나가는 것

`CHANNEL_OK` → `CALIB_STARTED` → `CALIB_PROGRESS` × N → 종결 응답
(`H_MATRIX` | `CALIB_FAIL` | `CALIB_CANCELLED`).

`CALIB_PROGRESS{phase, point_index, total, valid}`는 **서버가 합성**합니다 —
카메라는 이 방식에서 진행률을 안 올리는데 주행이 2~4분이라, 없으면 대기 화면이
그동안 통째로 빕니다.

## 2. 세션 소유권

잠금 자체는 이미 있었습니다 — `onMessage()` 전체가 `mtx_`로 직렬화되므로 두
`CALIB_START`가 동시에 통과하는 경합은 구조적으로 불가능합니다. **빠진 것은
"누가 쥐고 있는가"였습니다.**

`calibFromQt_`(bool) → `calibOwner_ ∈ {NONE, QT, ADMIN}`.

| 규칙 | 동작 |
|---|---|
| 시작 | 이미 세션이 있으면 `CALIB_FAIL{busy, owner:"QT"\|"ADMIN"}` |
| 취소 | **소유자만**. 아니면 `CALIB_FAIL{not_owner}` |
| 강제 회수 | 관리자 창의 `CALIB_CANCEL{force:true}`만 예외 → Qt엔 `CALIB_FAIL{preempted}` |
| 소유자 이탈 | QT 연결이 끊기면 QT 소유 세션 즉시 안전 정지 |
| `ESTOP` | 소유권과 **무관하게 항상** 통함 (캘리 경로를 타지 않음) |

**강제 회수를 예외로 둔 이유:** 로봇이 실제로 바닥을 굴러다니는 중인데 Qt 단말
앞에 사람이 없을 수 있습니다. 그때 관리자가 로봇을 못 세우면 안 됩니다. 다만
Qt에는 `CALIB_CANCELLED`가 아니라 `CALIB_FAIL{preempted}`가 갑니다 — 누르지도
않은 취소가 성공한 것처럼 보이면 안 되니까요.

### 같이 고친 기존 결함 4건

| 증상 | 원인 |
|---|---|
| 관리자가 취소를 누르면 **진행 중인 세션이 없어도 QT에 `CALIB_CANCELLED`가 감** | `cancelCalib()`이 origin을 안 받음 |
| 실패로 인한 중단(`capture_timeout` 등)이 Qt엔 "안전하게 중단했습니다"로 보임 | `onCalibStopped()`가 무조건 `CALIB_CANCELLED` |
| **QT가 끊겨도 주인 없는 로봇이 사각형을 계속 그림** | `onPeerChange`가 QT를 조기 return |
| 카메라만 끊긴 주행에서 **로봇이 계속 굴러감** | `failCalib`은 서버 상태만 정리하고 로봇을 안 세움 |

## 3. 폐합오차 로그 (진단 전용)

`idx 0`(출발 자리)과 `idx 8`(한 바퀴 돌고 온 자리)은 같은 물리 지점이므로 두
픽셀이 같아야 합니다. 차이가 곧 한 바퀴 누적된 주행 오차입니다 — **H가 없어도
성립하는 유일한 자기검증**입니다.

```
전: [INFO] 오도메트리 폐합오차 [채널 2] 34.2px (idx0=(...) idx8=(...))
후: [INFO] 오도메트리 폐합오차 [채널 2] 15.0px = 약 30mm (둘레 3000mm의 1.00%)
           | 스케일 0.500px/mm (4변 평균) | idx0=(300.0,1200.0) idx8=(315.0,1200.0)
```

스케일은 네 변의 실측 픽셀 길이 ÷ 명령 mm를 평균해 뽑습니다. 엄밀한 환산은
여전히 불가능하지만(H가 없으니), `34px`만으로는 심각한지 알 수 없어 로그가
사실상 안 읽혔습니다.

**🔴 진단 전용입니다. 이 값으로 세션을 실패시키거나 Qt에 알리지 않습니다.**
유효점 판정과 H 산출은 카메라 몫이고(wire §7) 서버가 뒤집으면 권한이 겹칩니다.
관리자 창은 서버 로그를 `LOG`로 중계받으므로 별도 전송 없이 이 줄을 봅니다.

한계는 코드 주석과 wire 스펙 §5-1에 명시했습니다 — **위치만 본다 / 오차가
상쇄되면 작게 나온다("작다 = 정확하다"는 성립 안 함) / 스케일이 거칠다.**

## 알려진 한계 — 캘리 주행의 코너 오차

로봇의 `TrimTurn`(회전 후 관성 잔차 능동 보정)이 **독립 도구
`calib_path_test`에만 있고 `main.cpp`의 서버 주행 경로에는 없습니다.** 그리고

정확도가 곧 호모그래피 정확도입니다.
