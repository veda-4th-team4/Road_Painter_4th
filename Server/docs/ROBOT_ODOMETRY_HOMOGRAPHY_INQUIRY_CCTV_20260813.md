## 1. 첫 통합 주행이 첫 지점에서 끊긴 원인

### 1-1. 서버 로그 (2026-08-12, 관리자창 개시, 채널 2, 200×200mm)

```
18:56:50 [INFO] (ADMIN) CALIB_START(robot_motion) 수락 [채널 2]
                m=200mm n=200mm start_corner=top_left (CW)
                -> ROBOT+CCTV 중계 + PATH(calib) 11-op 전송
18:56:53 [INFO] CALIB_CAPTURE 전송 [채널 2] point_index=0 world=(0.0,200.0)mm
         ...  15초간 무응답, 로봇은 정지점 0에서 state=IDLE 유지 ...
18:57:08 [WARN] 오도메트리 캘리 중단 [채널 2] reason=capture_timeout
                - CALIB_CAPTURE(point_index=0) ack를 15초 안에 받지 못했습니다
18:57:08 [INFO] CCTV 정지 확인 - 아직 ROBOT 대기 중
18:57:08 [INFO] 캘리 취소 완료 [채널 2] - ROBOT/CCTV 정지 확인됨 (ADMIN 개시)
```

로봇은 정상이었습니다. 경로를 받아 정지점 0에 서서 캡처 ack를 기다렸고,
그 ack가 오지 않아 서버가 세션을 접었습니다.

### 1-2. 원인 — `CALIB_CANCEL`은 되는데 `CALIB_CAPTURE`만 버려집니다

위 로그에서 **취소는 정상 동작했습니다** (`CCTV 정지 확인`). 즉 링크도,
세션 인지도 살아 있었습니다. 캡처 계열만 응답이 없었습니다.

두 메시지의 차이는 봉투 하나입니다:

| 메시지 | 봉투 | 8/12 결과 |
|---|---|---|
| `CALIB_CANCEL`, `CALIB_START`, `SELECT_CHANNEL` | `{"type":"CMD","payload":{"cmd":"<이름>",…}}` | ✅ 동작 |
| `CALIB_CAPTURE`, `CALIB_DONE` | `{"type":"<이름>","payload":{…}}` | ❌ 무응답 |

카메라 파서가 `"type":"CMD"`를 먼저 요구하도록 구현되면 `CALIB_CAPTURE`/
`CALIB_DONE`은 조건에 안 걸려 **조용히 버려집니다** — 에러도 로그도 없이요.
관측된 증상과 정확히 일치합니다.

**이 규칙이 8/12 시점 문서에 없었습니다.** 카메라 쪽 실수가 아니라 저희
스펙 누락입니다. 확정본 [§2-0](ROBOT_ODOMETRY_HOMOGRAPHY_WIRE_20260812.md)에
표로 명시해 뒀습니다(8/13 갱신).

서버 구현은 처음부터 이랬고 바꿀 계획이 없습니다 — `router_odocalib.cpp`의
`makeMsg("CALIB_CAPTURE", …)` vs `makeMsg("CMD", {{"cmd","CALIB_CANCEL"}})`.

### 1-3. ✅ 확인 요청 1

> **수신 측에서 봉투를 가리지 말고 명령 이름으로 판별**하도록 고쳐 주실 수
> 있을까요? 반영 후 알려주시면 바로 재시도하겠습니다.
>
> 이미 반영돼 있다면 **다른 원인**이므로 알려주세요 — 그 경우 서버가 보낸

## 2. `H_MATRIX` 번들에 wire §6 필수 필드가 비어 있습니다

### 2-1. 지금 서버에 저장된 번들 (`config/calib_latest.json`)

서버는 받은 번들을 **값 변경 없이 그대로** 저장·중계합니다(mm 보존 규약).
따라서 아래는 카메라가 실제로 보낸 내용입니다:

| 필드 (§6 기준) | 채널 2 | 채널 4 |
|---|---|---|
| `H_floor` | ✅ | ✅ |
| `unit` | ⚠️ 서버가 `"mm"`으로 찍어 넣음 | ❌ 없음 |
| `K` / `D` | ❌ 없음 | ❌ 없음 |
| `H_marker` | ❌ 없음 | ❌ 없음 |
| `image_size` | ❌ 없음 | ❌ 없음 |
| `coord_mode` | ❌ 없음 | ❌ 없음 |
| `method` | ❌ 없음 | ❌ 없음 |
| `marker_height_mm` | ❌ 없음 | ❌ 없음 |
| `origin_mm` / `canvas_mm` / `axis` / `calib_id` | ❌ 없음 | ❌ 없음 |

운영 서버 로그에 관련 WARN이 **90건** 쌓여 있습니다:

```
11:54:02 [WARN] 캘리브레이션(채널 2) unit 필드 없음 - mm으로 가정했다
                (규격상 필수. CCTV가 unit:"mm"을 실어 보내야 한다)
11:54:02 [WARN] 캘리브레이션(채널 2) image_size=(없음) - 이번 운용 규격은
                [2592,1520]다. Qt가 디코딩하는 영상 크기와 다르면 좌표가
                그만큼 틀어진다
```

### 2-2. 왜 이게 문제인가

- **`K`/`D` 없음**: `coord_mode:"undistort"` 전제인데 `K`/`D`가 없으면 서버가
  왜곡 보정을 **조용히 건너뜁니다**. 좌표는 그럴듯하게 나오고 렌즈 왜곡만큼
  틀립니다 (`src/calib.hpp` `Calib::hasKD` 게이트). 회신에서 "카메라가 K/D
  없으면 전송을 거부한다"고 하셨던 게이트가 이 경로에는 안 걸린 것 같습니다.
- **`image_size` 없음**: Qt가 디코딩하는 해상도와 캘리 기준 해상도가 다르면
  그 비율만큼 통째로 어긋납니다. 이번 운용 규격은 `[2592, 1520]`입니다.
- **`H_marker` 없음**: 오도메트리 방식이 **직접 측정**하는 값이라 이 방식의
  결과물 그 자체입니다.

### 2-3. ✅ 확인 요청 2

위 표는 **정적 앵커/체커보드 방식**으로 만들어진 번들입니다 — 오도메트리
세션이 완주한 적이 없으니 그 방식 번들은 아직 본 적이 없습니다. 그래서
질문을 둘로 나눕니다:

> **(a)** 오도메트리 세션이 `CALIB_DONE` 이후 올릴 번들은 §6 필드를 전부
> 채우는 게 맞습니까? (특히 `K`/`D`/`image_size`/`H_marker`/`method`)
>
> **(b)** 기존 방식 번들의 필드 누락은 별건으로 고쳐 주실 수 있을까요?
> 지금 운영 중인 좌표가 왜곡 보정 없이 돌고 있는 상태라, 오도메트리와
> 무관하게 시급합니다.

## 3. ✅ 확인 요청 3 — 8/12 통지 §2-1에 대한 이견 여부

8/12 통지에서 실패 사유를 **지점 수준 / 세션 수준**으로 나눈 건([§7](ROBOT_ODOMETRY_HOMOGRAPHY_WIRE_20260812.md))
"이견 있으시면 알려달라"고 열어 뒀는데 회신을 못 받았습니다.

| 수준 | reason | 서버 동작 |
|---|---|---|
| **지점** | `marker_not_found` / `not_settled` / `unmappable` | 그 점만 버리고 주행 계속 |
| **세션** | `no_intrinsics` / `session_conflict` / `detect_off` / `session_refused` / `store_failed` | 즉시 중단 |

> 이대로 진행해도 괜찮은지 한 줄만 주시면 확정하겠습니다.
> (이견 있으시면 서버 쪽 한 줄 수정입니다.)

## 4. 서버 쪽 변경 통지 (8/13) — 카메라 영향 없음

참고만 하시면 됩니다. **카메라가 고칠 것은 없습니다.**

1. **Qt도 세션을 개시할 수 있게 됐습니다.** 관리자창 전용이 아닙니다.
   카메라 입장에서는 `CALIB_START`의 출처만 다를 뿐 프로토콜이 동일합니다.
2. **`CALIB_PROGRESS`는 서버가 합성해 Qt로 보냅니다** (wire §2-2).
   정적 앵커 방식과 달리 **카메라는 진행률을 올리지 않습니다.**
3. **폐합오차를 서버 로그에 남깁니다** (wire §5-1). 시작점(idx 0)과 복귀점
   (idx 8)의 픽셀 차이입니다. **진단 전용** — 판정에 쓰지 않고, 임계값도
   없고, 카메라로 아무것도 보내지 않습니다.
4. 실패 사유 2종 추가: `preempted`(관리자창 강제 회수), `qt_offline`.
   서버가 판정하는 값이라 카메라는 받기만 합니다.
