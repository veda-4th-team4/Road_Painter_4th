# 펜 두께 보정 — 설계 검증 (2026-08-13)

- 상태: **구현 완료, 오프라인 회귀 통과. 실주행 검증 전**
- 배경: 실주행 결과 목표 사각형의 네 귀퉁이가 칠해지지 않음
- 관련: `docs/PROTOCOL_v2_ROBOT.md` §5.2~5.4 (펜 오프셋 불변식)

---

## 1. 문제

펜은 폭 **5cm** 짜리 마커인데, 현재 시스템은 펜을 **폭 0인 점**으로 취급한다.
코드 어디에도 펜 폭 개념이 없다(`pen_width` 류 심볼 검색 0건). `pen_offset_m`은
"마커 중심 ↔ 노즐"의 **진행방향 거리**일 뿐 폭과 무관하다.

### 왜 귀퉁이가 비는가

경계 코너를 원점, 내부를 +x/+y로 두고 폭 `w=5cm`, 반폭 `h=2.5cm`라 하면:

```
가로 구간 : 중심경로 y=2.5 위를 x=2.5 → 진행    도색 밴드: x∈[2.5, …], y∈[0,5]
세로 구간 : 중심경로 x=2.5 위를 y=2.5 로 도착    도색 밴드: x∈[0,5],  y∈[2.5, …]

           ┌──────────  ← 목표 경계
     ╱╱╱╱╱ │            [0,2.5]×[0,2.5] 사각형이
     ╱╱╱╱╱ │            어느 밴드에도 안 들어간다
     ──────┼──────
           │
```

**미도색 영역 = 한 변에 `h × h` 짜리 정사각형.** 사진의 빨간 빗금이 이것이다.

## 2. 제안된 공식 검증 (2026-08-13)

> `move 할 거리 = qt에서 받은 move 거리 + 펜두께/2`
> `펜 오프셋 보정할 거리 = 기존 펜과 마커 사이의 거리 - 펜두께/2`

`a = pen_offset_m = 0.150`, `w = 0.05`, `h = w/2 = 0.025`, 구간 길이 `L`,
꼭짓점 `V0 → V1`. 마커 중심은 펜보다 `a` **앞**에 있다.

| 단계 | 마커 중심 | 펜 위치 | 판정 |
|---|---|---|---|
| 시작 | `V0` | `V0 − a` | |
| 전진 `(a−h)` | `V0 + a − h` | **`V0 − h`** | ✅ 앞쪽 `h` 연장됨 |
| 노즐 down | | 도색 시작 `V0 − h` | ✅ |
| 도색 `(L+h)` | `V1 + a` | **`V1`** | ❌ 뒤쪽 연장 없음 |
| 노즐 up | | 도색 끝 `V1` | |
| 후진 `(a−h)` | **`V1 + h`** | | ❌ 꼭짓점 아님 |

### 어긋난 것 2개

**① 뒤쪽이 연장되지 않는다.** "앞뒤로 `h`씩"이 의도였는데 `+h`는 앞쪽 한 번에만
쓰인다. 뒤쪽까지 늘리려면 도색 거리가 `L + w`(= `L + 2h`)여야 한다.

> 다만 **닫힌 경로에서는 앞쪽만 늘려도 귀퉁이가 채워진다** — 다음 구간이 그
> 꼭짓점에서 `h` 앞서 시작하면서 이전 구간의 끝 공백을 덮기 때문이다. 열린
> 경로의 마지막 획만 `h` 짧게 끝난다.

**② 후진 후 마커가 꼭짓점에 없다.** `V1 + h`에 선다. 다음 구간은 "마커가
꼭짓점에 있다"를 전제로 회전·전진하므로 **꼭짓점마다 `h`씩 기준점이 밀린다.**
사각형 한 바퀴면 네 번 누적된다.

## 3. 수정된 공식

앞뒤 대칭으로 연장하고 꼭짓점 불변식을 지키려면:

```
전진 오프셋 =  a − w/2      (0.150 − 0.025 = 0.125)
도색 move   =  L + w        (앞 w/2 + 뒤 w/2)
후진 오프셋 =  a + w/2      (0.150 + 0.025 = 0.175)
```

검산:

| 단계 | 마커 중심 | 펜 위치 |
|---|---|---|
| 시작 | `V0` | `V0 − a` |
| 전진 `(a−h)` | `V0 + a − h` | `V0 − h` ✅ |
| 도색 `(L+2h)` | `V1 + a + h` | `V1 + h` ✅ |
| 후진 `(a+h)` | **`V1`** ✅ | |

앞뒤 `h`씩 연장 + 꼭짓점 불변식 유지. 전진과 후진이 **비대칭**(`a−h` vs `a+h`)
인 것이 핵심이다 — 도색 구간이 `w`만큼 길어진 것을 후진에서 되돌려야 한다.

## 4. 🔴 세 번째 문제 — MORE 피드백이 보정을 되돌린다

`src/router.cpp:563`:

```cpp
const double off = m.centerAheadByA ? P.pen_offset_m : 0.0;
const double tx = m.penTarget[0] + off * ux;
```

MORE 판정은 "마커 중심이 꼭짓점보다 `a` 앞에 있어야 한다"를 **하드코딩**하고
있다. 위 §3대로 고치면 실제 목표는 달라진다:

| op | 실제 목표 | 현재 코드가 믿는 값 | MORE가 하는 짓 |
|---|---|---|---|
| 전진 다리 | 꼭짓점 + `(a−h)` | 꼭짓점 + `a` | `h`만큼 **더 전진**시켜 보정 무효화 |
| 도색 move 끝 | 꼭짓점 + `(a+h)` | 꼭짓점 + `a` | `h`만큼 **되돌림** |
| 후진 다리 | 꼭짓점 | 꼭짓점 | 문제없음 |

**즉 코드를 §3대로만 고치면 MORE 피드백이 그 보정을 매번 취소한다.**

그리고 두 목표값(`a−h`, `a+h`)이 서로 다르므로 **`bool` 하나로는 표현할 수
없다.** `OpMeta::centerAheadByA`(bool)를 실제 거리값(double, 예:
`centerAheadM`)으로 바꿔야 한다.

## 4-1. 피드백을 "꺼야" 하는가 — 아니다, 목표를 고쳐야 한다

두께 보정은 **의도된 과주행**이다. 그래서 "피드백이 이걸 오차로 보고 되돌리지
않게 어떻게 끄지?"가 자연스러운 질문인데, **끄면 안 된다.**

MORE는 "마커가 있어야 할 자리 vs 실제 자리"의 차이를 잡는 장치다. **"있어야 할
자리"에 두께 보정을 포함시키면 피드백은 보정을 방해하는 게 아니라 보정을
지켜준다.** 끄면 오히려 두께만큼 늘린 그 지점이 무보정 상태가 된다.

| op | 노즐 | MORE 목표(`centerAheadM`) | 판단 |
|---|---|---|---|
| 오프셋 전진 | **up** | `a − w/2` | ✅ 유지 — 도색 시작점 정확도를 지킨다 |
| 도색 move | down | `a + w/2` | ✅ 유지 — 기존 동작과 동일(§4-2) |
| 오프셋 후진 | **up** | `0` | ✅ 유지 — 다음 꼭짓점 기준점을 지킨다 |
| 도색 arc | down | `a` | ✅ 유지 — 두께 보정 대상 아님(§6-2) |

**끄면 안 되는 결정적 이유**: `more_deadband_m`은 5mm인데 두께 보정은 25mm다.
목표를 안 고치면 MORE가 **매 boundary마다 반드시 발동해서**(25mm ≫ 5mm) 보정을
정확히 되돌린다. 목표를 고치면 이 문제 자체가 사라진다.

### 4-2. 다만 새로 생기는 것은 아니지만 남는 위험

도색 move의 MORE는 **노즐이 내려간 채** 실행된다(`closePaint`가 nozzle-up을 그
boundary 뒤에 넣기 때문). 음수 MORE가 나오면 젖은 선 위를 되짚어 문지른다.

- 이건 **2026-08-11에 "후진 허용, 문지름 감수"로 이미 결정된 기존 동작**이고,
  이번 변경이 만든 게 아니다.
- 다만 보정으로 종료점이 `w/2` 더 나가면서 **문지르는 구간도 그만큼 목표 경계
  바깥**이 됐다. 실주행에서 경계 밖 번짐이 눈에 띄면 이 항목을 다시 볼 것.
- `offset_feedback_test` [4]가 이 지점을 매번 출력한다(실패로 세지는 않음).

### 4-3. DRIFT / ALIGN

- **DRIFT**: `isPath && op=="move"`에서만 나간다. 도색 move는 해당되므로 계속
  나가고, 이건 직선을 곧게 유지하는 데 필요하다. 오프셋 다리는 `isPath=false`라
  원래 대상이 아니다. **변경 없음.**
- **ALIGN**: 직전 op이 `role=path`인 turn일 때만. 오프셋 다리는 turn이 아니다.
  **변경 없음.**

## 6. 확인이 필요한 것

### 6-1. Qt 경로가 이미 `w/2` 안쪽으로 들어와 있는가 (수직 방향)

이번 공식은 **진행방향(앞뒤)만** 다룬다. 폭 방향은 "중심경로가 경계에서
`w/2` 안쪽"이어야 밴드 바깥선이 경계에 정확히 닿는다.

- 이미 들어와 있다면 → 이번 수정만으로 해결
- 경계 위를 지난다면 → 도색이 경계 밖으로 `2.5cm` 삐져나간다 (**별개 문제**)

사진의 검은 선이 청록 경계에서 안쪽으로 보이나, 축척을 알 수 없어 단정 못 한다.
**Qt팀에 "경로 좌표가 도면 경계선인지, 경계에서 안쪽으로 오프셋된 값인지"
확인 필요.**

### 6-2. ARC 구간

호도 앞뒤로 `w/2`씩 늘려야 하는데 거리가 아니라 **각도**로 환산해야 한다:

```
Δθ = (w/2) / R_paint   [rad]
```

`R_paint`가 작을수록 각도가 커진다. 직선과 같은 방식으로는 안 되므로 별도 처리가
필요하다. **이번 수정 범위에 포함할지 결정 필요** (직선만 먼저 해도 사진의
사각형 케이스는 해결된다).

### 6-3. 펜 폭 실측

5cm는 마커 사양이다. 실제 도색 폭은 압력·속도·노면에 따라 다를 수 있으므로,
**직선 한 줄 긋고 자로 재서** `pen_width_m`에 넣는 편이 정확하다.
