## 1. 요청 사항

| # | 항목 | 우선순위 |
|---|---|---|
| **R-1** | `CALIB_START` 수신 처리 (현재 무시됨) | 🔴 **차단 요인** |
| **R-2** | `CALIB_STOPPED` — 정지 확인 ACK (신규) | 높음 |
| **R-3** | `CALIB_FAIL` — 주행 실패 보고 (신규) | 높음 |
| R-4 | TLS 접속 IP 검증 한 줄 추가 | 낮음 |

### R-1. `CALIB_START` 수신 처리 🔴

`RaspberryPi/src/main.cpp:66-115`의 CMD 분기가 `ESTOP` / `RESUME` / `ABORT_DRAW` /
조이스틱 / 노즐만 처리하고, **`CALIB_START`는 `else`로 빠져 조용히 버려집니다.**

계약의 `method`가 `"robot_motion"`인데 로봇이 그 주행 명령을 모르는 상태입니다.

서버는 Qt가 보낸 원본을 **그대로** 중계합니다:

```json
{"type":"CMD","payload":{
  "cmd":"CALIB_START",
  "ch":2,
  "request_id":"qt-1786320000000-1",
  "method":"robot_motion"
}}
```

**`ch` / `request_id`는 로봇이 보존하지 않아도 됩니다.** 서버가 세션 상관관계를
전부 들고 있으므로, 로봇은 "캘리브레이션 주행을 시작하라"로만 읽으시면 됩니다.
(Qt에 돌아가는 `H_MATRIX`에는 서버가 직접 `request_id`를 찍어 넣습니다.)

요청 사항:
- 캘리 주행 중 **노즐 up 유지**
- 기존 PATH 실행기를 재사용할지 별도 상태를 둘지는 **로봇팀 결정 사항**입니다.
  서버는 내부 방식에 의존하지 않고 R-2/R-3 응답만 기다립니다.

### R-2. `CALIB_STOPPED` — 정지 확인 ACK (신규 규격)

`CALIB_CANCEL`을 받아 **실제로 멈추고 노즐을 올린 뒤** 보내주십시오.

```json
{"type":"CALIB_STOPPED","payload":{}}
```

```
Qt   ──CMD{CALIB_CANCEL}──▶ 서버
서버 ──그대로 중계──▶ ROBOT  +  CCTV
ROBOT ──CALIB_STOPPED──▶ 서버   ┐ 둘 다 모여야
CCTV  ──CALIB_STOPPED──▶ 서버   ┘
서버 ──CALIB_CANCELLED──▶ Qt
```

- 한도: **5초** (`params().calib_cancel_ack_ms`)
- 한쪽이라도 없으면 서버가 Qt에 `CALIB_FAIL{reason:"cancel_failed"}`를 보냅니다

🔴 **`DRAW_ABORTED`와 의도적으로 다른 규약입니다.** 그건 "명령을 로봇에 전달했다"는
접수 ACK인데, 캘리 중에는 Qt가 전체 화면 대기 상태라 거기서 "중단됨"을 먼저 띄우면
**아직 굴러가는 로봇 쪽으로 사람이 걸어갑니다.** 그래서 서버는 확인하지 못한 것을
확인했다고 하지 않습니다.

> 참고: Qt팀이 `ROBOT_NOZZLE_HOMOGRAPHY_ACTION_ITEMS_20260810.md` §4.3에서
> "ABORT/ESTOP/연결 단절 각각에서 속도 0·노즐 up이 보장되는지"를 묻고 있습니다.
> 그 답에 따라 **`ABORT_DRAW`도 같은 "정지 확인 후" 규약으로 바꿀 수 있습니다.**
> 로봇이 정지 완료 ACK를 보낼 수 있다면 알려주십시오 — 서버는 어느 쪽이든 맞춥니다.

### R-3. `CALIB_FAIL` — 주행 실패 보고 (신규 규격)

```json
{"type":"CALIB_FAIL","payload":{"reason":"motion_failed","msg":"설명"}}
```

`reason`은 그대로 Qt에 전달되고, Qt는 `msg`를 조작자에게 표시합니다.

**이게 없으면 Qt는 서버 타임아웃(기본 3분)까지 대기 화면에 갇힙니다.** 서버가
자력으로 만들 수 있는 사유는 사전 검증 실패와 `timeout`/오프라인뿐이고,
`motion_failed`는 로봇만 아는 사실입니다.

### R-4. TLS 접속 IP 검증 (낮음)

`NetworkManager.cpp:62`가 `SSL_VERIFY_PEER`로 체인 검증은 하지만 **접속한 IP가
인증서에 들어있는지는 확인하지 않습니다.** CCTV는 이미 확인하고 있어서 로봇만
한 단계 약합니다.

```c
// SSL_CTX_set_verify 근처에 한 줄
X509_VERIFY_PARAM_set1_ip_asc(SSL_CTX_get0_param(ssl_ctx), "192.168.0.8");
```

서버 인증서 SAN에 `192.168.0.8`만 있으므로, 넣으시면 **주소를 잘못 설정했을 때
조용히 엉뚱한 곳에 붙는 대신 접속이 실패**합니다. 급한 항목은 아닙니다.

| | 체인 검증 | 접속 IP 검증 |
|---|:---:|:---:|
| CCTV | ✅ | ✅ |
| **로봇** | ✅ | ❌ ← R-4 |
| Qt | ❌ | ❌ (별도 요청: `QT_TLS_VERIFY_20260810.md`) |

## 2. ⚠️ 서버 동작 변경 — 로봇 코드 변경은 불필요하나 확인 필요

### 2-1. 🔴 수동 모드 래치 수정 — 주행 중 받는 메시지가 달라집니다

서버에 버그가 있었습니다. 조이스틱 명령이 서버를 "수동 모드"로 바꾸는데,
그 해제가 **새 도면(BLUEPRINT) 수신 때만** 되고 있었습니다.

그래서 아래 순서를 밟으면 —

```
도면 전송 → 조이스틱으로 로봇 위치 조정 → 작업 시작
```

— **그 작업 전체가 ALIGN / MORE / DRIFT 없이 개루프로 돌았습니다.**
시뮬레이터 실측:

| | GO 사유 "수동 모드" | ALIGN/MORE 판정 |
|---|---:|---:|
| 수정 전 | **26건 (전부)** | **0건** |
| 수정 후 | 0건 | 정상 수행 |

`START_DRAW` 시점에도 해제되도록 고쳤습니다 (접근 경로를 현재 pose에서 새로
만들기 때문에 래치를 유지할 이유가 없습니다).

🔴 **로봇 관점에서 중요한 점**: 예전에 `GO`만 받던 상황에서 이제
**`ALIGN` / `MORE` / `DRIFT`가 정상적으로 나갑니다.** 그 처리에 잠복해 있던 문제가
있었다면 이제부터 드러납니다. 주행 시험 때 확인 부탁드립니다.

### 2-2. 도색 중 수동 노즐 명령 차단

`NOZZLE_DOWN` / `NOZZLE_UP` / `PAINT_ON` / `PAINT_OFF`가 경로 실행 중에는
**로봇까지 가지 않습니다.**

예전에는 이 명령들이 수동 조작 차단 목록(조이스틱 5종)에 없어서 도색 중에도 그대로
통과했고, 서보가 뒤집히면 다음 nozzle op이 올 때까지 반대 상태로 그렸습니다.

**로봇 코드는 바꾸지 않으셔도 됩니다.** 대기 중에는 종전대로 동작하고,
점검용 수동 노즐 탈출구는 관리자 창(ADMIN 경로)에 남아 있습니다 — 그쪽은
의도적으로 차단 판정을 거치지 않습니다.

## 3. 로봇팀 회신 요청

### (a) 🔴 R-3 호출부 — 지금 유일하게 열려 있는 항목

`NetworkManager::SendCalibFail(reason, msg)`는 구현돼 있는데 **`main.cpp`에서
호출하는 곳이 없습니다.** 함수가 있어도 아무도 안 부르면 서버에는 아무것도
도착하지 않습니다.

캘리 주행이 실패하는 경로(모터 탈조, 시리얼 두절, 목표 지점 도달 실패 등)에서
불러주십시오. 없으면 그 실패가 **서버 타임아웃 3분 뒤에야** Qt에 드러납니다 —
조작자는 그동안 대기 화면에 갇힙니다.

```cpp
net_manager.SendCalibFail("motion_failed", "캘리 주행 중 목표 지점 도달 실패");
```

`reason`은 그대로 Qt에 전달되고 Qt는 `msg`를 화면에 띄웁니다.

### (b) main 병합 시점

현재 구현이 `feature/server-driven-v2`에만 있습니다. 서버는 `main` 기준으로
동작하므로 병합 전까지는 종단간 시험에서 쓰이지 않습니다.

### (c) `ABORT_DRAW`도 정지 확인 ACK 규약으로 바꿀지

R-2에서 `CALIB_STOPPED`를 100ms 정착 대기 후 보내주셨으니, 같은 방식을
`ABORT_DRAW`에도 적용할 수 있습니다. Qt팀이
`ROBOT_NOZZLE_HOMOGRAPHY_ACTION_ITEMS_20260810.md` §4.3에서 같은 것을 묻고
있습니다. **서버는 어느 쪽이든 맞춥니다.**

### (d) §2-1 수정 후 주행 시험 결과

`ALIGN`/`MORE`/`DRIFT`가 이제 정상적으로 나가는 상황에서 처리에 문제가 없는지
확인 부탁드립니다.
