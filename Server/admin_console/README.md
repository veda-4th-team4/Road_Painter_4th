# 관리자 창 (admin_console)

> **관리자 창이 뭐 하는 건데?** 에 답하는 문서.
> 관련: [../README.md](../README.md) · [docs/PROTOCOL](../docs/PROTOCOL.md) (ADMIN 장) · [docs/CALIBRATION](../docs/CALIBRATION.md)

카메라 캘리브레이션 도구 + 서버 로그 모니터 + 로봇 제어 패널을 겸하는 **웹 GUI** 다.
설치 기사가 현장에서 캘리브레이션과 로봇 점검을 이 창 하나로 처리한다는 전제로 만들었다.

---

## 1. 구조

서버(9000)에 **`ADMIN`** role 로 붙어서 두 가지를 한다.

1. **로그 엿듣기(TAP)** — 서버가 중계하는 모든 메시지의 사본을 받는다.
   QT ↔ ROBOT ↔ CCTV 트래픽을 실시간으로 볼 수 있다.
2. **로봇 제어** — `CMD`/`PATH` 를 서버에 보내면 서버가 ROBOT 에 전달한다.

카메라 좌표 통역을 위해 `CCTV` role 로도 하나 더 붙는다.

```
카메라 ──TCP(6100)──▶ [admin_console] ──HTTP(8083)──▶ 브라우저
                           │
                           └──TLS(9000, role=ADMIN + CCTV)──▶ [C++ 서버]
```

## 2. 화면 세 개

| 주소 | 화면 | 내용 |
|---|---|---|
| `http://<서버IP>:8083` | 카메라 캘리브레이션 | `K`/`D` 내부 파라미터, 호모그래피, LDC 왜곡 검사, 스냅샷 |
| `http://<서버IP>:8083/robot` | 로봇 제어 | ESTOP·RESUME·수동 조작·캘리 시작 + 상태 배너 |
| `http://<서버IP>:8083/logs` | 로그 모니터 | 서버 트래픽을 role 별로 필터해서 실시간 표시 |

## 3. 실행

보통은 서버의 `./start.sh` 가 자동으로 같이 띄운다. 직접 띄울 일은 포트를 바꿀 때 정도다.

```bash
./admin_console/start.sh
```

포트는 `admin_console/config.sh` 에서 바꾼다 (현 서버: 카메라TCP `6100`, HTTP `8083`, 스냅샷 `6101`).

```bash
cd admin_console && python3 web_gui.py [카메라TCP포트] [HTTP포트] [스냅샷포트]
```

서버가 다른 호스트에 있으면:

```bash
RP_SERVER_HOST=x.x.x.x python3 web_gui.py
```

⚠️ 카메라 앱이 `CAM_POSE` 를 보내는 대상(통역 다리)도 이 인스턴스의 TCP 포트로 맞춰야 한다.

⚠️ **같은 카메라를 바라보는 인스턴스는 한 개만 띄울 것.**
카메라는 설정된 포트 하나로만 접속한다. 다른 인스턴스가 이미 그 포트를 쓰고 있으면
포트가 겹치지 않게 조정해야 한다.

## 4. 🔑 로그인 게이트

어느 주소로 들어가든 **로그인 전에는 `/login` 화면만 뜬다.**

- 세션은 **브라우저별**이라 다른 PC 는 각자 로그인해야 한다.
- **브라우저를 닫으면 재로그인**이 필요하다(세션 쿠키).
- 상단 탭바의 **로그아웃** 으로 즉시 끊을 수 있다.
- 서버(9000) 연결이 끊기면 모든 세션이 무효화된다.

**왜 게이트를 뒀나** — 캘리 결과가 *그 시점에 로그인된 사용자*의 계정에 저장되기 때문이다.
로그인 없이 캘리를 끝내면 세션에만 남아 서버 재시작 시 사라지고
(`[WARN] 캘리브레이션 수신 - 로그인 사용자 없음, 세션에만 유지`),
**나중에 로그인해도 소급 저장되지 않는다.**
순서를 사람이 기억하게 하는 대신 게이트로 강제했다.

> 서버는 로그인 사용자를 **한 명만** 기억한다. 이후 Qt 가 다른 계정으로 로그인하면
> 저장 대상이 그쪽으로 바뀐다.

테스트 계정은 `python3 tools/seed_user.py` 로 만든다 (기본 `test`/`1234`).

## 5. 📋 로그 상한

`POS` tap 이 초당 수십 건씩 흘러 무한정 쌓이는 것을 막는 값들이다.
`rp_core.py` / `web_gui.py` 에서 조정한다.

| 대상 | 상한 | 비고 |
|---|---|---|
| `admin_console/gui.log` | **2 MB × 4개 (총 8 MB)** | 초과 시 자동 회전 (`gui.log.1`~`.3`) |
| 메모리 히스토리 (`LOG_HISTORY_MAX`) | **300줄** | 페이지를 열 때 브라우저로 한꺼번에 밀어넣는 양 — 크면 창이 버벅인다 |
| 로봇 제어 페이지 화면 | **200줄** | 곁다리 로그라 작게 |
| 로그 모니터 화면 | **400줄** (원본 버퍼 1000줄) | 전용 화면이라 넉넉히 |

`gui_err.log` 에는 파이썬 크래시 트레이스백만 쌓인다(평소엔 비어 있다).

## 6. 파일

| 파일 | 역할 |
|---|---|
| `web_gui.py` | HTTP 서버 + 세 화면의 HTML/JS |
| `rp_core.py` | 서버(9000) TLS 연결, TAP 수신, 로그 버퍼 |
| `cctv.py` | 카메라 TCP 연결, 좌표 통역, `ZONE_EVENT` 중계 |
| `start.sh` / `config.sh` | 기동 스크립트와 포트 설정 |
