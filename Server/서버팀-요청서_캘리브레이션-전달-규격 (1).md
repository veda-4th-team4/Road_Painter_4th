## 1. 목적과 범위

**전달 모델**: 서버가 캘리브레이션 번들을 보관하고, QT **로그인 성공 시점에 `LOGIN_OK` 로 함께 내려준다.**
QT 는 로그인 후 별도 요청 없이 즉시 좌표계를 사용한다.

| ID | 항목 | 성격 |
|---|---|---|
| **R-1** | 로그인 사용자 없을 때도 번들 영속 저장 | 🔴 **수정 요청 (MUST)** |
| **R-2** | `POSE` 정의 확정·회신 | **회신 요망** |
| R-3 | `unit` 필드 갱신 | 있으면 좋음 (QT 자체 방어 중) |
| C-1 ~ C-5 | 현행 동작 확인 | **회신만** (수정 불필요) |

**범위 밖 (QT 가 하지 않음)**: 캘리브레이션 수행, 호모그래피 계산·검증·재피팅, 마커 검출 기반 좌표 산출, 펜 오프셋 보정.

**전송 규약 (현행 유지)**: TCP, `\n` 구분 JSON Lines, `{"type":"<TYPE>","payload":{...}}`.
QT 는 미지의 `type` 을 무시하며 연결을 끊지 않는다.

## 2. 🔴 R-1 — 로그인 사용자가 없을 때도 번들을 저장해 주세요 (MUST)

### 현상

QT 로그인 로그가 항상 이렇게 나옵니다.

```
[10:25:02] 로그인 성공: hihi
[10:25:02] LOGIN_OK calib=null — 관리자 창 안내 필요
```

### 원인 (`router.cpp:432`)

```cpp
if (!currentUser_.empty() && users_.setCalib(currentUser_, bundle))
    logf("[INFO] 캘리브레이션 수신 ... 사용자 '%s'에 영속 저장", currentUser_.c_str());
else
    logf("[WARN] 캘리브레이션 수신 (mm->m 정규화) - 로그인 사용자 없음, 세션에만 유지");
```

번들이 **사용자 계정에 매달려** 저장됩니다. 그래서 CCTV(또는 관리자 창)가 캘리브레이션을 올리는 시점에 QT 로그인 세션이 없으면 `currentUser_` 가 비어 있고, 번들은 **메모리에만** 남습니다. 서버를 재시작하거나 다음에 로그인하면 사라집니다.

### 요청

캘리브레이션은 **현장(카메라+바닥) 속성**이지 사용자 속성이 아닙니다. 로그인 상태와 무관하게 보관해 주세요.

- 방식은 서버팀 재량입니다. 예: 계정과 분리된 전역 슬롯(`calib_latest.json` 등)에 저장하고, `LOGIN_OK` 때 계정별 값이 없으면 전역 값을 내려주기
- 서버 재시작 후에도 유지될 것
- CCTV 가 신규 번들을 발행하면 교체할 것

### 임시 우회 (요청 반영 전까지 QT 가 하고 있는 것)

1. QT 로 **먼저 로그인** → 그 상태에서 관리자 창에서 캘리브레이션 실행 (이러면 저장됩니다)
2. 또는 QT 설정 화면에 번들 JSON 을 직접 붙여넣기 (테스트용 임시 입력란)

운영에서 1번 순서를 매번 지키게 하는 건 현실적이지 않아 R-1 을 요청합니다.

## 3. R-2 — `POSE` 정의 확정 (회신 요망)

```json
{"type":"POSE","payload":{"x":0.0,"y":0.0,"theta_deg":0.0}}
```

메시지 형식 변경은 요청하지 않습니다. **아래 항목만 확정해 회신**해 주세요.

| 항목 | QT 가 코드에서 확인한 값 | 확인 |
|---|---|:---:|
| `x`, `y` 단위 | **미터** (`router.cpp:310` 주석, `std::round(p.x*1000)/1000`) — QT 도 미터로 처리 중 | ⬜ |
| `x`, `y` 좌표계 | `LOGIN_OK.calib` 의 월드 평면과 동일 원점·동일 축 | ⬜ |
| `x`, `y` 해상도 | 소수 3자리 = **1 mm** 양자화 (붓 폭 50 mm 대비 2% → QT 는 충분하다고 판단) | ⬜ |
| `theta_deg` 기준축·부호 | QT 전제: `+X` 축 기준 **반시계(CCW) 양수**, 범위 `[-180, 180]` | ⬜ |
| **발행 주기** | **(기재 요망)** — QT 는 이 주기로 로봇 위치·진행률을 갱신합니다 | ⬜ |

전제와 다르면 실제 정의를 회신해 주세요. **QT 가 값을 변환해 맞춥니다.**

> `theta_deg` 와 발행 주기는 코드만 봐서 확정할 수 없어 회신이 필요합니다.

## 4. R-3 — `unit` 필드 갱신 (있으면 좋음, 낮은 우선순위)

`normalizeBundleMmToM()` 은 `H_floor`/`H_marker` 만 ÷1000 하고 `unit` · `origin_mm` · `canvas_mm` 은 그대로 둡니다. 그래서 서버가 내려주는 번들은 **H 는 미터, `unit` 은 `"mm"`** 로 섞여 있습니다.

QT 는 이미 자체 방어하고 있으니 **급하지 않습니다.** H 로 국소 배율을 재서 `canvas_mm` · `image_size` 와 대조해 실제 단위를 판정하고, 선언값과 다르면 판정을 채택하고 경고를 남깁니다. 현장 번들 실측 결과:

| 입력 | r | 판정 |
|---|---|---|
| 원본 (mm) | 3.043 | mm ✅ |
| 서버 정규화 후 (m) | 0.003043 | m ✅ |

두 후보가 1000배 떨어져 있어 판정 경계까지 각각 96배 / 10배 여유가 있습니다.

여유가 되시면 정규화 후 `unit` 을 `"m"` 으로 바꿔 주시면 형식이 정직해집니다. 안 하셔도 QT 는 정상 동작합니다.

## 5. C-1 ~ C-5 — 현행 동작 확인 (수정 불필요, 회신만)

QT 가 서버 소스에서 읽어 확인한 내용입니다. **틀린 항목만 알려주세요.**

### C-1 `LOGIN_OK` 스키마 (`router.cpp:403`)

```cpp
srv_.sendTo(replyRole, makeMsg("LOGIN_OK",
    {{"id", id}, {"calib", stored}, {"cam_ip", users_.getCamIp(id)}}));
```

```json
{"type":"LOGIN_OK","payload":{
  "id":"hihi",
  "cam_ip":"192.168.0.12",
  "calib": {
    "calib_id":   "2026-07-29-1411",
    "created_at": "2026-07-29T14:11:46+09:00",
    "image_size": [1920, 1080],
    "coord_mode": "undistort",
    "unit":       "mm",
    "K": [[1283.53,0,924.43],[0,1283.02,515.83],[0,0,1]],
    "D": [-0.42876,0.283696,-0.000125,0.000616,-0.142204],
    "H_floor":  [[0.002007,0.0000423,-1.735665],
                 [-0.0000291,-0.001923,1.967736],
                 [-7.5245e-7,0.000819,1]],
    "H_marker": [[...]],
    "marker_height_m": 0.25,
    "origin_mm": [0,0],
    "canvas_mm": [900,600],
    "axis":      "x_right_y_up"
  }
}}
```

- ✅ **`H_floor` 의 0·1행은 미터 단위** (정규화 결과). QT 가 이 전제로 동작합니다.
- ✅ `K` · `D` 는 픽셀 단위이므로 정규화 대상이 아님 (`calib.hpp:58`)
- ✅ 보관 중인 번들이 없으면 `"calib": null` — QT 는 좌표계 미설정 상태로 진입하고 사용자에게 안내
- ⬜ `H_marker` · `marker_height_m` 는 서버가 시차(parallax) 보정에 쓰는 값으로 이해했습니다. **QT 는 사용하지 않습니다** (작도는 바닥 평면 = `H_floor`). 맞는지 확인 부탁드립니다.

### C-2 다음 필드는 **정규화·중계 과정에서 지우지 말아 주세요** (MUST)

| 필드 | QT 가 쓰는 용도 |
|---|---|
| `coord_mode` | H 의 **입력 픽셀 공간** 판별. `"undistort"` 면 QT 가 점을 먼저 왜곡보정한 뒤 H 를 적용하고, RTSP 화면에 그릴 때는 반대로 왜곡을 다시 태웁니다 |
| `canvas_mm` | TopView 캔버스 크기 + **§4 단위 검산의 기준** |
| `image_size` | 캘리브 해상도와 실제 영상 해상도 불일치 경고 + **§4 단위 검산의 기준** |
| `calib_id` | 어느 번들이 적용 중인지 화면 표시·로그 대조 |
| `K`, `D` | 렌즈 왜곡 보정 (없으면 광각 가장자리가 휨 — 실측 16.4 mm → 2.0 mm 오차) |

`canvas_mm` 이나 `image_size` 가 빠지면 §4 검산이 불가로 떨어져 `unit` 선언값을 그대로 믿게 됩니다. 즉 **R-3 를 안 고치실 경우 이 두 필드는 필수**입니다.

### C-3 `H_MATRIX` push (`router.cpp:428`)

로그인 이후 번들이 교체되면 서버가 정규화된 번들을 QT 로 push. 페이로드 형식은 `LOGIN_OK.calib` 과 동일. **현행 유지, 변경 요청 없음.** push 미구현이어도 QT 는 재로그인으로 갱신 가능합니다.

### C-4 `BLUEPRINT` 수용 규약 (`router.cpp:169~213`) — 검증 완료

QT 전송분이 서버에 그대로 접수되는 것을 코드로 확인했습니다.

| 항목 | 서버 요구 | QT 전송 |
|---|---|---|
| `points` | 2개 이상 숫자쌍, **미터** | ✅ 미터 |
| `paint` | `points` 와 길이 동일, 아니면 무시 | ✅ 다르면 아예 안 실음 |
| `program[].op` | `MOVE`/`TURN`/`NOZZLE`/`ARC` | ✅ 동일 4종 |
| `program[].v` | **정수 필수**, 없으면 program 전체 거부 | ✅ 정수 |
| `BLUEPRINT_OK` | `{points, paint, program}` 개수 회신 | ✅ 수신 후 대조·경고 |

- ✅ 서버는 `planProgram_` 을 가공 없이 로봇에 중계 (`router.cpp:536`)
- ⬜ **참고 (서버 문제 아님)**: 로봇 `PathFollower.cpp:223` 에 `MOVE`/`TURN` 분기만 있고 `else` 가 없어, `ARC`/`NOZZLE` 세그먼트를 만나면 속도 0 으로 정지합니다. QT 는 `ARC` 전송을 **기본 OFF** 로 두고 있습니다. 로봇팀 확인 사항입니다.
- ⬜ 프로토콜 폐지 필드(`pen_offset_m` · `pivot` · `speed_mps` · `speed_dps`)는 QT 가 **전송하지 않습니다.** `SET_SPEED` 도 보내지 않습니다.

### C-5 그 외

- ✅ QT 는 마커 픽셀 좌표(`POS`)를 수신하지 않습니다. 전송 불필요.
- ✅ QT 는 `CALIB_START` 를 보내지 않습니다 (캘리브레이션 시작은 관리자 창 담당).
- ✅ `ACK` / `LOGIN_FAIL` / `REGISTER_OK` / `REGISTER_FAIL` / `STATUS` / `PEERS` / `SET_CAM_IP_OK` / `SET_CAM_IP_FAIL` / `DRAW_DONE` / `DRAW_FAIL` 현행 유지. 변경 요청 없음.
- ✅ 종료 신호는 `DRAW_DONE` 하나. QT 는 자체 완료 판정을 하지 않습니다.
