## 1. ✅ R-1 — 로그인 사용자 없을 때도 번들 영속 저장 (구현 완료)

지적하신 원인 분석이 정확합니다. 번들이 `currentUser_`에 매달려 있어, 아무도 로그인하지
않은 상태에서 올린 캘리브레이션은 메모리에만 남고 서버 재시작 시 유실됐습니다.

### 구현 내용

제안하신 방식(전역 슬롯 + 로그인 시 대체)을 그대로 채택했습니다.

| 항목 | 내용 |
|---|---|
| 저장 위치 | **`config/calib_latest.json`** (계정 파일과 분리) |
| 저장 시점 | `H_MATRIX` 수신 시 **로그인 상태와 무관하게 항상** |
| 조회 규칙 | `LOGIN_OK` 때 **계정에 자기 캘리가 없으면 전역 값**을 내려줌 |
| 우선순위 | **계정 값 > 전역 값** — 계정에 고정해둔 번들을 전역이 덮지 않음 |
| 교체 | CCTV가 신규 번들을 발행하면 전역 슬롯을 갱신 |
| 재시작 | 파일이므로 유지 |

계정 파일과 분리한 이유: `config/users.json`은 비밀번호 해시 때문에 버전관리 제외
대상이고 백업·교체 주기가 다릅니다. 캘리브레이션은 "현장 속성"이라는 지적에 맞춰
독립 파일로 뒀습니다.

### 로그 변화

로그인 사용자가 없는 경우가 더 이상 경고가 아닙니다.

```
(이전) [WARN] 캘리브레이션 수신 (mm->m 정규화) - 로그인 사용자 없음, 세션에만 유지
(이후) [INFO] 캘리브레이션 수신 (평면 번들, mm->m 정규화, H_marker 포함, K/D 포함)
              - 로그인 사용자 없음, 전역 슬롯에 영속 저장 (다음 로그인 때 전달됨)
```

### 임시 우회는 이제 불필요합니다

QT가 하고 있던 **"QT로 먼저 로그인 → 그 다음 관리자 창에서 캘리"** 순서를 지키지 않아도
됩니다. 설정 화면의 번들 JSON 붙여넣기 입력란도 §7 계획대로 제거하셔도 됩니다.

## 2. ✅ R-2 — `POSE` 정의 확정 회신

**QT 전제가 5개 항목 모두 정확합니다.** 변환 없이 그대로 쓰시면 됩니다.

| 항목 | 확정 값 | 근거 |
|---|---|---|
| `x`, `y` 단위 | **미터** | `router.cpp` POS 핸들러 — `std::round(p.x*1000)/1000` |
| `x`, `y` 좌표계 | **`LOGIN_OK.calib`의 월드 평면과 동일 원점·동일 축** | pose는 `H_marker`로 변환한 월드 mm를 ÷1000한 값. `H_floor`와 같은 월드 좌표계 |
| `x`, `y` 해상도 | **소수 3자리 = 1 mm 양자화** | 동일 |
| `theta_deg` 기준축·부호 | **`+X`축 기준 반시계(CCW) 양수, 범위 `[-180, 180]`** | `atan2(fy-by, fx-bx)`의 반환 범위를 그대로 도(度)로 변환 |
| **발행 주기** | **서버는 주기를 만들지 않습니다.** CCTV `POS` 1건당 `POSE` 1건을 즉시 발행(스로틀·보간·집계 없음) → **주기 = CCTV의 `POS` 주기** | POS 핸들러에서 무조건 전송 |

### 발행 주기 보충

현장 관측값은 **15~30 Hz**이며, 이는 카메라 쪽 프레임 처리 속도에 따라 달라집니다.
CCTV팀이 동적 ROI 추적으로 검출 속도를 올리는 작업 중이라 이 값은 앞으로 변동될 수
있습니다. **서버가 상한을 걸지 않으므로 QT는 상한을 가정하지 마시고**, 화면 갱신
주기는 QT 쪽에서 필요한 만큼 솎아 쓰시길 권합니다.

또한 **`POSE`는 CCTV가 로봇 마커를 검출하지 못하면 아예 발행되지 않습니다** (좌표를
구할 수 없으므로 그 프레임은 조용히 버려집니다). 즉 주기가 균일하지 않고 **끊길 수
있습니다** — 진행률 표시가 "멈춘 것"과 "안 보이는 것"을 구분해야 하면 QT 쪽에서
마지막 수신 시각 기준 타임아웃을 두시는 게 안전합니다.

## 3. ✅ R-3 — `unit` 필드 갱신 (구현 완료)

정규화 후 `unit`을 `"m"`으로 갱신합니다. QT의 자체 검산(§4 국소 배율 판정)과 선언값이
이제 일치하므로 경고가 뜨지 않습니다.

`origin_mm` · `canvas_mm`은 **의도적으로 mm를 유지합니다** — 필드 이름이 단위를 명시하고
있고, QT가 단위 검산의 기준으로 쓴다고 하셨기 때문입니다. `K` · `D`는 픽셀 단위라
정규화 대상이 아닙니다(QT 확인 내용과 동일).

## 4. 🔴 신규 — 평면 번들의 `H` 키 문제 (서버에서 수정 완료)

**QT-REQ-SRV-001 rev.3 작성 이후(2026-07-30) 서버에 생긴 문제입니다.** QT는 알 수 없었던
사안이라 공유합니다. **QT 대응은 필요하지 않습니다.**

### 무슨 일이었나

서버가 QT-REQ-CCTV-001 **평면 스키마**(바닥 H의 키 이름이 `H_floor`가 아니라 `H`)를
읽을 수 있게 되었습니다. 그런데 **저장·중계하는 JSON은 들어온 키 이름을 그대로 유지**해서,
평면 번들로 올리면 `LOGIN_OK.calib`에 `H_floor`가 없고 `H`만 있었습니다.

QT는 `calib.H_floor`만 보므로(C-1) **좌표계를 잡지 못합니다 — 에러 없이 조용히.**
관리자 창에서 어느 버튼을 눌렀는지가 QT 동작을 갈랐습니다.

| 관리자 창 버튼 | 서버 내부 계산 | QT가 받는 키 | QT 동작 |
|---|---|---|---|
| `QT-REQ-CCTV-001 형식으로 채우기` | 정상 | `H` | ❌ 못 읽음 |
| `구 형식(H_floor/H_marker)` | 정상 | `H_floor` | ✅ 읽음 |

### 수정 내용

저장·중계 전에 **`H_floor` 별칭을 추가**합니다. 원본 `H`도 지우지 않고 남깁니다.

- QT는 기존대로 **`H_floor`만 보면 됩니다** (rev.3 C-1 전제 그대로 유효)
- QT-REQ-CCTV-001 형식도 보존되어, 번들을 발행한 CCTV 쪽과 대조 가능
- 두 값은 항상 동일합니다 (`H == H_floor`)
- 명시적 `H_floor`가 이미 있으면 그것을 우선합니다 (덮지 않음)

**출력 스키마가 입력 형식에 따라 달라지지 않게** 서버에서 통일한 것이므로, CCTV팀이
어느 형식으로 발행하든 QT가 받는 모양은 같습니다.

## 5. C-1 ~ C-5 확인 결과

### 정확한 항목 (그대로 유효)

- **C-1** `LOGIN_OK` 스키마 — 정확합니다. 예시 JSON도 실제와 일치합니다.
  - ✅ `H_floor`의 0·1행은 미터 (정규화 결과)
  - ✅ `K` · `D`는 정규화 대상 아님
  - ✅ 보관 번들이 없으면 `"calib": null`
  - ✅ **`H_marker` · `marker_height_m`는 서버 전용입니다** — 문의하신 내용 확인해
    드립니다. 로봇 마커가 바닥에서 떠 있어 생기는 시차(parallax) 보정에만 씁니다.
    **QT는 무시하셔도 됩니다** (작도는 바닥 평면 = `H_floor`가 맞습니다).
- **C-2** 나열하신 6개 필드(`coord_mode`·`canvas_mm`·`image_size`·`calib_id`·`K`·`D`)를
  **정규화·중계·저장 과정에서 지우지 않습니다.** 평면 번들은 payload 전체를 그대로
  보존하므로 추가 필드도 함께 전달됩니다. **MUST 준수 확인.**
- **C-3** `H_MATRIX` push — 구현되어 있습니다. 번들이 교체되면 정규화된 번들을 QT로
  전송하며, 형식은 `LOGIN_OK.calib`과 동일합니다.
- **C-4** `BLUEPRINT` 수용 규약 — 표 5개 항목 전부 정확합니다. `program[].v` 정수 필수
  (없으면 program 전체 거부 후 서버 폴백) 포함.
- **C-5** 전부 정확합니다. 폐지 필드(`pen_offset_m`·`pivot`·`speed_mps`·`speed_dps`)와
  `SET_SPEED`를 보내지 않으신다는 점 확인했습니다.

### 🔧 정정 2건

**① §7 비고 — CCTV팀에 `H_floor`로 발행 요청할 필요가 없어졌습니다**

> rev.3 §7: *"`H` 단일 키로 올리면 `calibFromJson()`이 실패해 서버가 번들을 폐기합니다"*

**현재는 아닙니다.** 서버가 `H`를 바닥 행렬로 읽고, §4의 별칭 처리로 `H_floor`를 붙여
내려줍니다. **CCTV팀에 키 이름 변경을 요청하지 않으셔도 됩니다** — 오히려 관리자 창의
기본 버튼이 평면 형식(`H`)입니다. 이미 전달하셨다면 "둘 다 동작한다"고 정정 부탁드립니다.

**② C-1 예시의 `"unit": "mm"`**

R-3 반영으로 이제 **`"m"`**으로 내려갑니다.

## 7. 비고 — QT가 알아두면 좋은 서버 동작 하나

**서버는 QT 연결이 끊겨도 `currentUser_`(현재 로그인 사용자)를 유지합니다.**
다른 계정으로 로그인할 때만 교체됩니다.

실질적 영향: **"로그인 사용자 없음"은 서버 기동 후 아무도 한 번도 로그인하지 않은
구간에서만 발생**합니다. 그래서 R-1이 주로 문제가 됐던 시나리오는 **서버를 새로 띄우고
설치 기사가 바로 캘리브레이션하는 경우**였고, 이제 해결됐습니다.

세션이 끊긴 뒤 올라온 번들은 마지막 로그인 계정에도 함께 저장됩니다. 이는 기존 동작이며
이번 변경으로 달라진 점은 없습니다. 문제가 된다면 별도로 알려주세요.
